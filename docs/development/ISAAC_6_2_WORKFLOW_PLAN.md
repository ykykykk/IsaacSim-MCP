# Isaac Sim MCP 6.2 工作流升级方案

日期：2026-11-12  
设计基线：`ykykykk/IsaacSim-MCP` / `56a6a65`  
状态：核心 A—D 已完成代码实现，实际接口与边界见 `docs/WORKFLOW_6_2.md`；尚未运行本轮测试/场景验收。第 14 节仍为后续独立范围。本文件不授权自动修改场景或发布。

## 1. 结论与目标

继续维护现有 Tim 派生实现，不更换 MCP 底座，不另建求解器。
目标不是最大化工具数，而是让复杂 USD 工程中的查询、修改、构建与保存形成可理解、可追踪的完整流程。

本轮核心交付：

1. 修正多层 USD 编辑与回滚的实际范围。
2. 把运行身份、实现支持和历史验证记录分开。
3. 将 MPM 构建纳入统一任务查询，准确表达阶段、取消与失败。
4. 打通配置来源、临时修改、运行配置及定向保存。
5. 提供按工作领域选择的工具集与一致的安装配置。

继续使用 NVIDIA 官方文档 MCP；现场控制与文档检索保持独立。
当前本机宿主实际为 `6.2.0-rc.14`，不能写成已验证所有正式 6.2 构建。

### 明确不做

- 不重写现有机器人、传感器、ROS 2、Replicator 或求解器实现。
- 不迁移到另一套 MCP 框架，不升级无关依赖。
- 不增加网页控制台、服务数据库、云调度或完整强化学习平台。
- 不通过 MCP 高频发送逐帧控制命令；实时控制留在 Kit 脚本、控制器或 Action Graph。
- 不自动播放、保存、重建、重放失败写操作；不修改 Bauma USD 来演示功能。
- 不以本次方案为由运行测试、lint、构建、仿真或性能探针。

## 3. 已确认的基线与缺口

| 项目 | 当前事实 | 改进 |
|---|---|---|
| 工具数量 | legacy 134、consolidated 103；是注册数量 | 保留接口，另加领域选择，不把数量当验收 |
| 层回滚 | stage_composition 快照只记录 Root/Session；部分写入使用当前编辑目标 | 覆盖真实写入层，恢复失败不得标成功 |
| 能力矩阵 | 仍引用 6.0.1 的 PhysX 验证证据 | 结构化记录 evidence_version，不能直接等同于当前 6.2 验证 |
| 宿主身份 | 已有 PID、日志绑定；曾被 Full 共用配置加载旧 MCP | 再返回加载路径、实例标识、扩展代码版本 |
| MPM 重建 | 可排队、读取状态；Kit update 内同步构建 | 任务 ID、阶段记录、明确不可中断边界 |
| MPM 修改 | 写 Session，带 stage/hash 检查 | 补配置发现、来源及 authored/runtime 差异 |
| 保存 | save_stage_as 是 scratch 根层导出，不含 Session | 单独提供定向提交，不改变原工具含义 |
| 保存到源插件 | root_stack 排除 Session；失败恢复场景层但拥有层可留下未保存的部分修改 | 不能直接包一层宣称完成 Session 保存；先补精确接口与拥有层恢复 |
| 安装资料 | 新本机配置与旧版本/端口说明并存 | 分离通用默认与本机配置，统一有效配置输出 |
| HTTP | 有 Host 限制，没有身份认证 | 本轮以本地 stdio 为默认，不推荐无认证公开入口 |

上述缺口来自源码阅读；除前次明确记录的空宿主加载和只读检查外，不包含新增现场复现。

## 4. 架构与所有权

```text
Codex / 其他 MCP 客户端
  ├─ 官方文档 MCP：版本化 API 与示例
  └─ 本项目 MCP：工具选择、输入契约、统一结果
         ↓ 现有 stdio/本机 TCP
      Isaac 扩展
         ├─ 实例/Stage 身份及能力报告
         ├─ USD 编辑事务与来源查询
         ├─ 统一任务路由
         └─ 可选领域提供者
              ├─ sany.granular_mpm：配置、构建、运行物料
              └─ bauma.save_to_source：拥有层定位与定向保存
```

所有权规则：

- MCP 仓库拥有协议、适配、任务查询与通用 USD 编辑逻辑。
- MPM 插件拥有配置语义、构建阶段、GPU 资源生命周期与实际物料；MCP 不复制这些状态。
- 保存插件拥有资产源定位与迁移规则；先调整其公开 API，再接入 MCP。
- Bauma 项目拥有资产布局、源文件与场景参数；通用仓库不写死其 prim 路径。
- 复用已有模块；只为事务和上下文等确有多个调用点的能力增加小型共享模块，不做全库重构。

## 5. 模块 A：可靠的实例与能力信息

### 5.1 运行身份

扩展现有 get_capabilities / get_runtime_status，不新增重复诊断工具。
建议新增字段（设计接口，不代表已经实现）：

| 字段 | 含义 |
|---|---|
| instance_id | 本次宿主启动生成的唯一标识，区别 PID 重用 |
| stage_id | 当前 Stage 生命周期标识；同一文件重开也变化 |
| root_identifier | USD 根层身份 |
| edit_target | 当前层身份及必要的路径映射信息 |
| extension_origin | 实际扩展目录与 Python 模块路径 |
| extension_code_version | Python 包的实际版本，不只取 Kit 的显示版本 |
| source_revision | 安装元数据提供的提交号；没有可靠信息则 unknown，不每次查询启动 Git |
| provider_capabilities | MPM/保存插件的接口版本与可用操作 |

保留已有 PID、日志和运行后端。不能仅按目录名判断宿主版本。
版本不匹配时只阻止依赖不兼容契约的写操作；允许诊断和其他已支持的只读操作。

### 5.2 能力与证据分离

分别返回 implementation、availability、evidence：

- implementation：implemented / unsupported。
- availability：available / missing_dependency / not_ready / unknown。
- evidence：记录测试环境、宿主版本、后端、日期、来源和覆盖范围。
- 当前版本没有证据时为 unverified；历史 6.0.1 记录继续保留，不能抹掉，也不能升级成 6.2 证据。

旧响应字段保留；若旧字段含义容易误导，在同一处生成正确语义并附迁移说明。
只查询环境，不因为缺依赖自动启用插件或安装软件。

## 6. 模块 B：真实的多层 USD 事务

### 6.1 事务范围

事务只承诺“选定 USD 层的内存编辑”恢复，不承诺恢复 GPU、求解器或已经写入磁盘的多文件状态。
Sdf.ChangeBlock 只能合并通知，不能冒充回滚事务。

执行流程：

1. 明确操作的 Stage、目标 prim、目标层和映射后的 spec 路径。
2. 在修改前建立完整的将写入层集合；无法确定写入范围的操作不能进入原子批处理。
3. 对这些层保存有容量约束的内存快照，包括本次可能修改的拥有层。
4. 检查可编辑性、实例代理/变体等路径映射是否受支持，拒绝无法明确定位的写入。
5. 在正确 EditTarget 下执行，完成操作所需的局部返回值/回读处理。
6. 失败时恢复全部触及层；逐层记录恢复结果。恢复失败返回 partial/rollback_failed 和具体层，不返回假成功。
7. 恢复调用前的编辑目标，不永久切换用户的编辑层。

快照不是磁盘 before 备份，不复制外部贴图、payload 或完整工程。
超出快照预算时修改前报错，指出哪些层太大；不退化为“无回滚继续写”。
首轮使用清楚的层快照方案，不为了节约理论开销引入复杂的通用 USD diff 引擎。

### 6.2 并发与预览

- 预览返回有界 plan_id、Stage 身份、目标层指纹和具体将改字段。
- 应用前检查受影响内容是否仍符合计划；只检查相关层/字段，不遍历全工程。
- 计划过期或用户已修改相关内容时返回 stale_plan，先重新预览；不覆盖新改动。
- 进入队列的写请求绑定 Stage 生命周期，不能在用户切场景后落到新 Stage。
- 相关写操作在 Kit 主线程串行执行；不让工作线程直接操作 USD/PhysX。
- 现有 legacy 工具不突然增加必填参数；新工作流使用显式上下文，旧工具保留并逐步接入内部一致的事务机制。

### 6.3 有界撤销

仅对本 MCP 完成的纯 USD 内存事务提供 transaction_id 和有限期撤销。
撤销前检查事务结束后的层指纹；后续用户修改涉及同层时不盲目覆盖。
保存磁盘、物料重建和实时仿真不声称可由该撤销恢复。
此能力随事务实现自然提供，不建立跨应用的全局撤销系统。

## 7. 模块 C：MPM 任务与构建生命周期

### 7.1 扩展现有任务体系

request_mpm_rebuild 保留名称及 preview 默认值，真实提交返回统一 job_id。
get_job_status / list_jobs / cancel_job 通过提供者路由识别 MPM，不再建一套重复的 MCP 任务工具。
get_mpm_status 保留为场景/运行物料总览，关联 active_job_id。

每个构建任务至少记录：

- job_id、instance_id、stage_id、配置 prim。
- 请求时的 authored_config_hash、effective_config_hash。
- 排队/开始/结束时间、当前阶段、阶段耗时。
- 状态、取消能力、错误原因、当前是否仍有可用物料。
- 构建成功后物料使用的配置 hash。

建议状态：queued → running → succeeded / failed / cancelled。
另有 cancel_requested；客户端失去联系返回 unknown/unreachable，不把它直接改成 failed。
宿主重启后未完成任务标记 interrupted，不自动重建或恢复播放。
客户端等待超时与任务执行失败分开，不因 MCP 请求超时就改写物料任务状态。

### 7.2 分阶段构建

由粒子插件定义真实阶段，初步按实际构建顺序整理为：

1. 配置和依赖准备。
2. 场景/碰撞数据准备。
3. 释放旧物料的不可逆边界。
4. 粒子、求解器及 GPU 资源建立。
5. 显示绑定与就绪状态发布。

这些阶段需落实到现有函数，不为了呈现进度虚构百分比。
能安全让出执行权的阶段之间使用 Kit 调度继续执行；涉及 USD/PhysX 的工作留在主线程。
无法拆开的同步求解器/GPU 调用明确标记 non_interruptible，不能承诺期间 MCP 必然响应。

将最近任务阶段写入小型有界状态快照，绑定 instance/job，并标记更新时间。
仅用它在主线程忙时报告“最后已知阶段”，不把旧快照冒充实时状态，也不由后台线程访问求解器。
先复用现有 runtime status 存储方式，不引入数据库。

### 7.3 取消、失败与内存

- 排队任务可以直接取消。
- 执行中的任务只在已设计的安全点兑现取消；返回 cancel_requested 不等于 cancelled。
- 非可取消调用中返回原因，不能强杀用户 Kit 来实现取消。
- 保留现有“不同时保有两套大型粒子存储”的内存约束，不为回滚复制一套 GPU 物料。
- 旧物料已释放后新构建失败，准确返回 runtime_absent，不声称旧仿真已恢复。
- 保留上次配置与错误记录，但是否重建旧配置由后续明确请求决定。
- GPU 致命故障需要宿主重启时报告 restart_required，不自动重放构建。

## 8. 模块 D：配置来源、修改与保存闭环

### 8.1 三种状态明确区分

统一展示：磁盘/拥有层已写入配置、当前组合配置（含 Session）、已构建物料配置。
有差异时分别报告 requires_rebuild 与 requires_save；两者不能混用。
补充配置发现，列出已加载场景中的配置 prim；不自动加载全部 payload 以搜索配置。
未加载内容明确标记未检查范围。

查询属性时可按请求返回值、单位依据、来源层、覆盖链、最终生效意见与候选拥有层。
只读字段/范围由调用者指定，结果分页或限额；不默认下载粒子数组或整场景属性。
未知单位显示 unknown，不能给任意属性猜单位。

### 8.2 保存提供者要先补的接口

当前保存插件不能直接承担 Session 参数提交：它的 root_stack 明确排除 Session，迁移行为按子树而不是按本次选定字段。
因此必须在保存插件中增加小型、明确的公开接口，再由 MCP 调用：

1. 解析选定属性的拥有层与路径映射。
2. 生成精确属性级提交计划，列出源覆盖、目标层、受影响引用实例。
3. 在 save=False 模式下应用选定属性，完整覆盖源层和拥有层的内存恢复。
4. 明确区分内存应用与磁盘保存，保存失败保留具体错误及未完成文件清单。

沿用现有材质/引用路径处理，保持相对引用。
不将 Session 内的仿真位置、显示数据、运行缓存或其他用户改动整层复制到资产。
不依赖默认“第一个引用就是拥有者”；遇到不明确的拥有层要求显式选择。
共享资产只报告当前已知影响范围，不能假装已扫描所有其他工程。

### 8.3 用户操作流程

```text
发现配置 → 查看来源/当前值 → 预览参数修改
         → 应用到 Session → 显示需要重建
         → 用户要求时重建 → 读取任务与物料状态
         → 用户要求保存 → 预览选定属性提交
         → 提交到指定拥有层 → 返回磁盘保存与 Session 清理结果
```

参数修改不隐式重建；构建成功不隐式保存；保存不隐式播放。
preview=false 只表示接口执行模式，不代替上层用户授权。

### 8.4 磁盘边界

- 首轮优先支持一次明确的拥有层保存，不承诺多文件原子提交。
- 需要保存多个文件时列出顺序和结果；部分文件成功时返回 partial，不笼统声称全部回滚。
- 失败后的补救操作必须绑定同一提交记录，先确认实际文件状态，不盲重发整个保存流程。
- 默认不生成 USD before 备份；保留已有备份。
- 保存完成后只移除本次明确迁移的 Session 意见，保留其他覆盖。
- save_stage_as 继续保持原来的根层导出语义，不把它悄悄改成 flatten 或完整备份。

## 9. 工具设计：少新增，强化已有接口

以下为拟定接口，实施时以实际模块契约确定最终 schema；不宣称已经可调用。

| 接口 | 变化 |
|---|---|
| get_capabilities / get_runtime_status | 扩展身份、插件接口与证据字段 |
| get_stage_composition / get_typed_attribute | 增加可选来源与编辑目标信息 |
| apply_stage_batch | 修正事务范围，返回真实恢复结果及 transaction_id |
| get_mpm_config | 支持读取 authored/effective/runtime 差异，不改变原字段含义 |
| get_mpm_status | 关联 active_job、配置一致性与最后构建结果 |
| request_mpm_rebuild | 返回统一任务身份，不自动执行其他动作 |
| get_job_status / list_jobs / cancel_job | 路由到 MPM 提供者，统一生命周期 |
| list_mpm_configs（新增） | 分页发现已加载的配置 prim |
| preview_source_commit（新增） | 预览明确属性到拥有层的保存计划 |
| commit_source_changes（新增） | 根据计划提交，返回内存/磁盘结果 |
| undo_stage_transaction（新增） | 只撤销仍满足前置条件的纯 USD 内存事务 |

不会为了凑数把一个字段拆成一个工具，也不把所有操作塞进任意代码执行工具。
新工具使用清楚的输入结构和只读/破坏性提示；提示仅用于客户端理解，不能代替执行层检查。
错误保留原始原因与部分完成状态；不能用空结果或默认值伪装成功。

## 10. 工具集与安装产品化

### 10.1 工作领域选择

保留 legacy / consolidated / full 的现有含义；另加与名称合并模式正交的领域选择。
提供 core、scene、physics、robotics、mpm 等领域预设，公共核心只注册一次。
你的默认组合选 core + scene + physics + mpm；完整 legacy 仍可使用。
工具清单由现有注册来源生成，不维护第二份手写计数。

领域在 MCP 启动时确定，不随场景或插件加载动态改变工具列表，避免客户端缓存失效。
插件未启用时保留明确的 unavailable 状态；不偷偷开启。
减少工具列表是提升可理解性的设计选择，不承诺未经测量的 token 或成功率收益。

### 10.2 配置一致性

- 提供统一的“有效配置”解析与展示：显式启动参数优先，其次环境/项目配置，最后文档化默认值。
- 本机保留 6.2 / 8876；通用发行版不写死 F 盘或用户名，不自动改用户全局环境。
- 服务端、扩展与启动器使用同一份生成配置或显式传入值，消除 8766/8876 静默不一致。
- 宿主状态文件按实例/端点区分；本机扫描根仍限定 6.2。
- 安装记录列出源码、venv、扩展联接、日志路径和可选插件；不复制旧缓存或覆盖其他版本。
- 从安装资料中分离本机历史记录，统一 README、环境样例与版本说明。
- 显式列出 MPM 与保存插件所需 API 能力；缺少时只禁用对应操作，不让通用 MCP 整体启动失败。

### 10.3 远程访问

本轮不开发 OAuth 服务，不把开放网络入口当作默认功能。
保留本地 stdio 工作流；远程 HTTP 在有独立认证/授权方案前不作为推荐安装路径。
修改公开文档，明确 Host 校验不是认证；不得以开启 Funnel 作为“完成远程安全部署”。
如以后明确需要远程控制，再单独设计认证、写权限和客户端隔离，不顺带部署公网入口。

## 11. 实施顺序与交付拆分

| 阶段 | 内容 | 涉及仓库 | 规模 | 完成边界 |
|---|---|---|---|---|
| A1 | 实例身份、证据语义、提供者能力 | MCP | 小—中 | 不再混淆旧源码/旧验证与当前宿主 |
| A2 | USD 真实层事务、回滚结果 | MCP | 中 | 事务范围明确，失败状态真实 |
| B1 | MPM 配置发现、三态差异、任务 ID | MCP + MPM | 中 | 一次构建有唯一身份且可追踪 |
| B2 | 构建阶段、安全取消点、最后状态快照 | MPM + MCP | 大 | 不伪装可中断，不复制整套粒子存储 |
| C1 | 精确拥有层提交 API、补齐拥有层恢复 | 保存插件 | 中—大 | 能处理选定 Session 属性，不整层迁移 |
| C2 | 保存预览/提交与事务撤销工具 | MCP + 保存插件 | 中 | 修改—构建—保存闭环，部分失败可解释 |
| D | 领域工具集、统一配置、文档与发布准备 | MCP | 中 | 别人可理解安装，现有用户可继续使用 |

依赖：A1/A2 为基础；B1 → B2；A2 → C1 → C2；D 在接口稳定后收尾。
按完整小改动提交，不把整个方案堆成一次大重构。实施前从当时实际 HEAD 建立 `codex/6.2-workflow-v1`，保留无关改动。
规模不是工期承诺；主要不确定性在构建器可拆分边界和 USD 资产拥有层映射。

## 12. 验收设计与执行授权

以下是实施后的验收题目，不是本次执行指令。
默认代码/文档修改不自动运行测试、构建、lint、仿真、截图或独立验证脚本。
安装升级只做一次与目标相关的基本检查；更广验收由用户明确要求后执行。
正常操作内部的参数检查与返回结果回读是产品行为，不等于额外开展一轮测试。

| 范围 | 用户授权验收时的最小场景 | 判定 |
|---|---|---|
| 身份 | 加载目标扩展后只读查询 | 实例、路径、版本一致；历史证据版本单独列出 |
| 多层回滚 | 专用小型 scratch 层组合，在第二步故意失败 | 全部触及层恢复；未触及层不变；恢复失败不报成功 |
| 过期计划 | 预览后修改相关属性/切 Stage | 拒绝旧计划，不写入新 Stage |
| MPM 查询 | 小配置/未构建状态 | 正确区分三态，不启动构建 |
| MPM 任务 | 专用小粒子样本，显式重建 | job_id 唯一、状态终结、实际配置 hash 对应 |
| 取消 | 排队阶段和一个受支持的安全点 | 请求与完成分开；资源状态正确 |
| Session 保存 | 小型引用资产，含一个无关覆盖 | 只提交选定属性，无关覆盖保留，重开后的组合语义正确 |
| 保存失败 | 目标只读或可控写入失败 | 明确哪些内存/磁盘步骤完成，不自动吞错 |
| 兼容 | 既有必要只读入口与新领域列表 | 旧名称/参数仍可用，新提供者缺失不影响无关工具 |

不从上述局部检查扩大到全量传感器、ROS、机器人、所有 GPU 或性能测试。
不拿正式 Bauma 场景做故意失败试验；不为验收改生产物料或车辆。
如果用户未要求运行，交付写明“已实现、未进行本轮运行验收”，不宣称测试通过。

## 13. 发布与回退

- 本方案不创建 tag、GitHub Release 或推送；后续发布需对应授权。
- 保留原 MIT 许可和上游历史，使用已配置的 upstream 跟踪 Tim。
- 发布说明按实现、历史证据、本次实际检查三部分写，不继承未经重跑的全量通过结论。
- MCP 与粒子/保存插件分别提交，交付记录三个组件的对应版本/接口能力。
- 升级前结束受影响宿主，避免热重载触发大场景重建；保留旧源码与联接目标。
- 回退配置和插件应按匹配组合回退，不只降 MCP 而保留不兼容提供者。
- 纯内存事务可在有效条件下撤销；磁盘保存和旧物料释放不冒充可自动逆转。
- 回退不删除用户资产、已有备份、日志或其他环境，也不生成新的 before USD。

## 14. 后续独立阶段：记录与回放

第一轮闭环完成后，再考虑显式启动的运行记录任务：

- 记录选定关节、关键 prim 位姿、仿真时间、配置 hash 和坐标/单位元数据。
- Kit 内部按指定频率采样，MCP 负责启动、停止、查询与导出，不逐帧传输。
- 回放分为运动学重现和重新施加控制，两者分别标识，不声称物理结果必然一致。
- 不默认录制所有粒子或摄像机；媒体与大数组继续使用已有 artifact 机制。
- 专用于装载机/挖掘机的动作与参数比较，暂不绑定 DROID、ROS 或某种训练平台。

这不是首轮完成条件，不因“未来还能做”而拖延核心交付。

## 15. 设计完成定义

本方案已明确首轮范围、责任仓库、接口方向、失败语义、实施依赖、验收边界与回退方式。
实施完成定义是核心 A—D 范围交付、文档与实际状态一致；不是工具数量达到某个新整数。
对本用户最重要的结果是：改哪里看得见、重建哪次分得清、保存哪些层说得准、失败后留下什么状态讲得明白。
